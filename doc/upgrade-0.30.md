## Taxonomy importer corrections

The nonempty rehearsal demonstrated two upstream 0.30.9 importer defects:

1. Importing category filters replaced an earlier scope-filter assignment on the same component.
2. Reimporting a component filter with omitted `participatory_space_manifests` compared nil with the stored empty array, creating a duplicate.

`lib/tasks/emvi_taxonomy_compatibility.rake` adds a version-limited maintenance adapter. It unions existing and imported component filters and normalizes the missing manifest list for lookup. It loads only with Rake/maintenance tasks, not regular web boot, and leaves the framework fork unchanged. Tests cover both defects, repeat-import stability, translated child taxonomies, resource assignments, metric conversion and separation between organizations. Recheck/remove the adapter when changing framework releases.

The German fixture merges scope and area roots because both translate to `Bereiche`. Their children and filters remain distinct after the adapter. This also matters for production organization 5. Review its real plan and decide whether to use different root names before importing; changing a root name after import can create another root rather than rename the first. Do not blindly rerun `make_plan` after editing a reviewed plan.
